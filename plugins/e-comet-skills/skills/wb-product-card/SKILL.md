# Карточка товара WB

## Workflow

**Главное правило:** вызовите `browser_job` ровно один раз и сразу выполните полученную авторизацию через `execute_browser_job`. Не декодируйте JWT и не воспроизводите `trigger_url` текстом.

0. **Только для Claude:** обязательный первый шаг — фактически вызвать `browser_job` по шагу 1. Служебные статусы клиента и отсутствие tool в текущем списке не доказывают проблему с авторизацией и не отменяют вызов. Если tool не виден, подождите несколько секунд и повторите поиск до 3 раз, затем всё равно попытайтесь вызвать его. Говорите об авторизации только после соответствующей ошибки фактического вызова `browser_job` или `execute_browser_job`; иначе вернитесь к шагу 1. Если фактический вызов завершился ошибкой, сообщите пользователю только подтверждённую ею причину понятным языком, без названий tools и внутренних статусов. Не добавляйте догадок и рекомендаций, не следующих из ошибки.

Передавайте 1–50 уникальных положительных артикулов.

**Codex/ChatGPT Desktop:** выполните оба MCP-вызова внутри одного `exec`. Не разделяйте их между разными `exec`, не вызывайте `store()` и не выводите `triggerUrl` через `text()`:

```js
const authorization = await tools.mcp__e_comet__browser_job({
    job: { type: 'product_card', articles: [791050753, 913357757] },
});
if (authorization.isError) {
    text(authorization);
    exit();
}
const triggerUrl = authorization.structuredContent?.trigger_url;
if (typeof triggerUrl !== 'string') {
    text(JSON.stringify({ ok: false, code: 'BROWSER_JOB_TRIGGER_MISSING' }));
    exit();
}
const result = await tools.mcp__e_comet_local__execute_browser_job({ triggerUrl });
text(result);
```

Если подключён stage-сервер, используйте соответствующее доступное имя `browser_job` вместо `mcp__e_comet__browser_job`. Токен должен существовать только в локальной JS-переменной этого `exec`.

**Claude Cowork и Claude Code CLI:** вызовите удалённый `browser_job` с тем же descriptor, затем сразу вызовите `execute_browser_job` без `triggerUrl`:

```json
{}
```

Desktop hook подставит точное значение автоматически. Служебные статусы клиента и отсутствие tool в текущем списке не доказывают проблему с авторизацией. Если tool не виден, подождите несколько секунд и повторите поиск до 3 раз, затем всё равно попытайтесь сделать фактический вызов. Сообщайте только подтверждённую фактическим вызовом причину понятным языком, без внутренних названий tools и недоказанных рекомендаций.

Используйте компактный массив `products` из ответа. Полные ответы WB сохранены локально в NDJSON по `resultPath`.

`browser_job` передаёт backend только описание разрешённого задания и возвращает подписанный JWT с ограниченным сроком действия. Сами ответы WB идут локально: MCP → WebSocket → расширение → вкладка WB → обратно в локальный файл. Не открывайте вкладки и не управляйте DOM/CDP.

Если локальный tool сообщает, что расширение не подключено, один раз вызовите `local_bridge_status` и попросите пользователя открыть Chrome с установленным и обновлённым расширением e-Comet и хотя бы одной авторизованной вкладкой `wildberries.ru`.

`trigger_url` одноразовый. Если `browser_job` не вернул авторизацию из-за ошибки в аргументах, исправьте аргументы и повторите весь flow один раз. Ошибку handoff или подписи автоматически не обходите и не повторяйте с вручную переданным токеном; покажите подтверждённую причину пользователю.

## Поля результата

У товара доступны best-effort поля:

- основное: `nmId`, `name`, `brand`, `supplier`, `supplierId`, `rating`, `feedbacks`, `pics`;
- цены: `priceRub.basic`, `product`, `logistics`, `return`, `cashback`;
- остатки: `quantity.total`, `quantity.byWarehouse`, `quantity.bySize`;
- контент: `vendorCode`, `subject`, `rootSubject`, `colors`, `options`, `description`;
- состояние: `status`, `ok`, `error`, `units`.

`quantity.byWarehouse` содержит идентификатор `wh`, имя склада `warehouse`, количество `qty` и число строк `rows`.
Имя добавляется best-effort из локального справочника расширения; если его нет, показывайте `wh <id>`, не придумывайте название.

`resultPath` не является кэшем. Читайте только путь, возвращённый текущим `execute_browser_job`, и только если компактного `products` не хватило для ответа. Чтение `resultPath` не требует повторного `browser_job` или `execute_browser_job`. Не ищите и не переиспользуйте файлы прошлых пользовательских заданий.

Каждая строка NDJSON в `resultPath` имеет вид `{ jobId, nmId, key, url, response }`. Исходное тело WB находится в `response.data.body`; локальные имена складов, если доступны, — в `response.warehouseNames`.

## Ответ пользователю

- Цена — `priceRub.product`, старая/базовая цена — `priceRub.basic`.
- Общий остаток — `quantity.total`, по складам — `quantity.byWarehouse`, по размерам — `quantity.bySize`. Это моментальный снимок на время запроса.
- Склейка — `colors`, характеристики — `options`, описание — `description`, артикул поставщика — `vendorCode`.
- Не оставляйте сырые имена WB-полей в пользовательском ответе, а булевы значения показывайте как «да/нет»: `imt_id`/`imtId` — ID склейки, `subjectId` — ID предмета, `vendorCode` — артикул поставщика, `need_kiz` — обязательная маркировка.
- Если нужны сырые `stocks`, показывайте время доставки одним числом `time1 + time2`, а не двумя техническими полями.
- Для частичного результата верните успешные товары и явно перечислите ошибки по остальным.
- Не утверждайте, что товар отсутствует на WB, если запрос завершился сетевой ошибкой.
