# Карточка товара WB

## Workflow

**Главное правило:** после получения `trigger_url` не вызывайте `browser_job` второй раз в рамках этого пользовательского задания. После ответа `execute_browser_job` анализируйте его результат; единственное исключение для повтора `execute_browser_job` описано ниже.

0. Не выдумывайте ошибку авторизации. Отсутствие `browser_job` в списке инструментов и статусы клиента «требует авторизации» или «подключается» не доказывают, что пользователь не авторизован. Подождите несколько секунд и повторите поиск инструмента до 3 раз. Если он так и не появился, сообщите только, что MCP tool `browser_job` недоступен. Об авторизации говорите исключительно после явной ошибки фактического вызова `browser_job` или `execute_browser_job`; покажите её сообщение без догадок.

1. Вызовите удалённый e-Comet tool `browser_job`:

   ```json
   { "job_type": "product_card", "articles": [791050753, 913357757] }
   ```

   Передавайте 1–50 уникальных положительных артикулов.
2. Сразу передайте неизменённый `trigger_url` из ответа в локальный tool:

   ```json
   { "triggerUrl": "<trigger_url>" }
   ```

   Имя tool — `execute_browser_job`. Не декодируйте и не исправляйте URL/JWT.
3. Используйте компактный массив `products` из ответа. Полные ответы WB сохранены локально в NDJSON по `resultPath`.

`browser_job` передаёт backend только описание разрешённого задания и возвращает подписанный JWT с ограниченным сроком действия. Сами ответы WB идут локально: MCP → WebSocket → расширение → вкладка WB → обратно в локальный файл. Не открывайте вкладки и не управляйте DOM/CDP.

Если локальный tool сообщает, что расширение не подключено, один раз вызовите `local_bridge_status` и попросите пользователя открыть Chrome с установленным и обновлённым расширением e-Comet и хотя бы одной авторизованной вкладкой `wildberries.ru`.

`trigger_url` одноразовый. Если `browser_job` не вернул `trigger_url` из-за ошибки в аргументах, исправьте аргументы. Если `execute_browser_job` вернул `BROWSER_JOB_SIGNATURE_INVALID` или точную ошибку `Invalid browser job token signature`, один раз повторите только `execute_browser_job`, заново взяв неизменённый `trigger_url` из исходного ответа `browser_job`. Не вызывайте `browser_job` повторно и не берите строку из аргументов неудачного вызова. Если единственный повтор также отклонён, покажите ошибку пользователю. Другие ошибки авторизации автоматически не повторяйте.

## Поля результата

У товара доступны best-effort поля:

- основное: `nmId`, `name`, `brand`, `supplier`, `supplierId`, `rating`, `feedbacks`, `pics`;
- цены: `priceRub.basic`, `product`, `logistics`, `return`, `cashback`;
- остатки: `quantity.total`, `quantity.byWarehouse`, `quantity.bySize`;
- контент: `vendorCode`, `subject`, `rootSubject`, `colors`, `options`, `description`;
- состояние: `status`, `ok`, `error`, `units`.

`quantity.byWarehouse` содержит идентификатор `wh`, имя склада `warehouse`, количество `qty` и число строк `rows`.
Имя добавляется best-effort из локального справочника расширения; если его нет, показывайте `wh <id>`, не придумывайте название.

`resultPath` не является кэшем. Читайте только путь, возвращённый текущим `execute_browser_job`, и только если компактного `products` не хватило для ответа. Чтение `resultPath` не требует повторного `browser_job` или `execute_browser_job`. Не ищите и не переиспользуйте файлы прошлых пользовательских заданий.

Каждая строка NDJSON в `resultPath` имеет вид `{ jobId, nmId, key, url, response }`. Исходное тело WB находится в `response.data.body`; локальные имена складов, если доступны, — в `response.warehouseNames`.

## Ответ пользователю

- Цена — `priceRub.product`, старая/базовая цена — `priceRub.basic`.
- Общий остаток — `quantity.total`, по складам — `quantity.byWarehouse`, по размерам — `quantity.bySize`. Это моментальный снимок на время запроса.
- Склейка — `colors`, характеристики — `options`, описание — `description`, артикул поставщика — `vendorCode`.
- Не оставляйте сырые имена WB-полей в пользовательском ответе, а булевы значения показывайте как «да/нет»: `imt_id`/`imtId` — ID склейки, `subjectId` — ID предмета, `vendorCode` — артикул поставщика, `need_kiz` — обязательная маркировка.
- Если нужны сырые `stocks`, показывайте время доставки одним числом `time1 + time2`, а не двумя техническими полями.
- Для частичного результата верните успешные товары и явно перечислите ошибки по остальным.
- Не утверждайте, что товар отсутствует на WB, если запрос завершился сетевой ошибкой.
