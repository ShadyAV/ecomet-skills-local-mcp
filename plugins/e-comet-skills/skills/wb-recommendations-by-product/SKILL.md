# Рекомендации WB по товару

## Workflow

**Главное правило:** после получения `trigger_url` не вызывайте `browser_job` второй раз в рамках этого пользовательского задания. После ответа `execute_browser_job` анализируйте его результат; единственное исключение для повтора `execute_browser_job` описано ниже.

0. **Только для Claude:** обязательный первый шаг — фактически вызвать `browser_job` по шагу 1. Служебные статусы клиента и отсутствие tool в текущем списке не доказывают проблему с авторизацией и не отменяют вызов. Если tool не виден, подождите несколько секунд и повторите поиск до 3 раз, затем всё равно попытайтесь вызвать его. Говорите об авторизации только после соответствующей ошибки фактического вызова `browser_job` или `execute_browser_job`; иначе вернитесь к шагу 1. Если фактический вызов завершился ошибкой, сообщите пользователю только подтверждённую ею причину понятным языком, без названий tools и внутренних статусов. Не добавляйте догадок и рекомендаций, не следующих из ошибки.

1. Вызовите удалённый e-Comet tool `browser_job`:

   ```json
   {
     "job": {
       "type": "recommendations_by_product",
       "articles": [
         { "nm": 791050753, "pages": 1 },
         { "nm": 913357757, "pages": 5 },
         { "nm": 1244492882 }
       ]
     }
   }
   ```

   Передавайте до 20 артикулов. `{nm}` без `pages` означает всю обнаруженную полку (до 60 страниц), `{nm, pages}` — заданную глубину до 60 страниц.
2. Сразу вызовите локальный `execute_browser_job`, передав неизменённый `trigger_url`. Для первых N рекомендаций добавьте `productLimitTotal`, для поиска конкретных товаров — `productNmIds`:

   ```json
   { "triggerUrl": "<trigger_url>", "productLimitTotal": 20 }
   ```

3. Используйте `articles[].pages[].products`; полные WB-ответы сохранены локально по `resultPath`.

`browser_job` передаёт backend только описание разрешённого задания и возвращает подписанный JWT с ограниченным сроком действия. Ответы WB через backend не идут. Не декодируйте JWT, не открывайте вкладки и не управляйте DOM/CDP.

Если расширение не подключено, вызовите `local_bridge_status` и попросите пользователя открыть Chrome с обновлённым расширением e-Comet и хотя бы одной авторизованной вкладкой `wildberries.ru`.

`trigger_url` одноразовый. Если `browser_job` не вернул `trigger_url` из-за ошибки в аргументах, исправьте аргументы. Если `execute_browser_job` вернул `BROWSER_JOB_SIGNATURE_INVALID` или точную ошибку `Invalid browser job token signature`, один раз повторите только `execute_browser_job`, заново взяв неизменённый `trigger_url` из исходного ответа `browser_job`. Не вызывайте `browser_job` повторно и не берите строку из аргументов неудачного вызова. Если единственный повтор также отклонён, покажите ошибку пользователю. Другие ошибки авторизации автоматически не повторяйте.

`resultPath` не является кэшем. Читайте только путь, возвращённый текущим `execute_browser_job`, и только если компактного `articles` не хватило для ответа. Чтение `resultPath` не требует повторного `browser_job` или `execute_browser_job`. Не ищите и не переиспользуйте файлы прошлых пользовательских заданий.

Каждая строка NDJSON в `resultPath` имеет вид `{ jobId, nmId, page, url, response }`. Исходное тело WB находится в `response.data.body`.

## Ответ пользователю

- Группируйте результат по `sourceNmId`.
- Используйте готовую сквозную позицию `globalPosition`; `position` — место на странице.
- Для списка показывайте артикул, название, бренд, `priceRub.product`, рейтинг и отзывы.
- Помечайте рекламу только при `promoted: true`.
- При статусе `partial` или `failed` не утверждайте полноту полки; укажите число успешных и неуспешных страниц.
- При `truncatedByLocalLimit: true` полка длиннее локального предела в 60 страниц: явно скажите, что результат обрезан, даже если все запрошенные страницы получены успешно.
- Рекомендации — снимок на момент запроса и могут меняться.
