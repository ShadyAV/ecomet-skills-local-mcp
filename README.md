# e-Comet — тестовый локальный MCP

Версия тестового пакета: **2026.9.6**.

Этот marketplace устанавливает только **e-comet-local**. Удалённый MCP в плагин не включён: используется отдельно установленный **stage MCP e-Comet**. Повторно подключать stage или production remote MCP не нужно.

Репозиторий marketplace: https://github.com/ShadyAV/ecomet-skills-local-mcp

## Обновление

Обновите установленный плагин из этого тестового marketplace и начните новую задачу, чтобы клиент загрузил новую конфигурацию MCP и хуков.

Для локального сервера нужен Node.js 22 или новее, доступный в PATH. Для браузерных операций нужно совместимое расширение e-Comet в Chrome и авторизованная вкладка соответствующего маркетплейса.

## Что обновлено

- Пакеты отчётов Ozon Seller: один browser_job, один локальный вызов, последовательное выполнение элементов.
- Индексы itemIndex, причина пропущенной работы stopReason и корректные результаты отказа до исполнения.
- Подтверждённые фазы выполнения через прямое и peer-соединение: начатый отчёт не выдаётся за пропущенный при обрыве связи.
- Сохранение готовых XLSX при частичном завершении и отдельная обработка CREATE_OUTCOME_UNKNOWN без автоматического повтора.
- Хуки Claude/Codex для авторизации пакетных отчётов через отдельно подключённый stage.
- Автоматический выбор первой готовой Seller-вкладки без просьб сфокусировать её. Переключение компаний не добавлено.

## Границы тестирования

Обновление этого репозитория обновляет плагин, но не устанавливает новую Chrome extension. Для пакетных операций нужна сборка расширения с соответствующими capabilities и протоколом фаз.

Общая аналитика Ozon остаётся production-disabled в расширении до отдельной квалификации. Наличие локального инструмента не означает, что эта возможность уже включена в установленном расширении.

Stage подписывает запросы для настоящего кабинета Ozon; это не sandbox маркетплейса. Автоматического повторного создания отчётов после неопределённого результата нет.

Изменения перечислены в [CHANGELOG](CHANGELOG.md).

## Запуск в текущем Codex

Используется Codex-манифест с обычными доверенными hooks. Native Agent Plugins manifest не включён: Codex 0.153.4 при его наличии не загружает hooks. Если host не передаёт каталог данных локальному MCP, тестовый launcher сохраняет результаты в `.e-comet/test-plugin-output/e-comet-skills` внутри домашнего каталога пользователя. Явные настройки каталогов сохраняются; авторизация по-прежнему передаётся только доверенными hooks.

Это тестовая конфигурация: она разрешает официальный ID расширения и ID локальной сборки из используемого тестового checkout. Production-конфигурация основного плагина не изменяется. Должна быть активна только нужная копия расширения.

Тестовая копия расширения имеет отдельные настройки входа. Сохраните ключ своего e-Comet-аккаунта в её вкладке «Ключ расширения». Вход в Ozon Seller не заменяет вход в e-Comet.
