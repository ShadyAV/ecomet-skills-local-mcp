# e-Comet — тестовый локальный MCP

Версия пакета: **2026.9.10**. Этот marketplace устанавливает только `e-comet-local`; отдельно установленный stage MCP сохраняется, production remote не добавляется.

Пакет работает с тестовым расширением **`kfdeggpflkbafbjdhbcmfgeibhdnmaio`**. При обычном запуске принимается только этот ID; ID production-расширения и произвольные другие расширения отклоняются. [Тестовое расширение](https://chromewebstore.google.com/detail/kfdeggpflkbafbjdhbcmfgeibhdnmaio).

MCP запускается напрямую через Node.js 22+, без отдельного launcher и development-переменных. Доверенные Claude/Codex hooks передают подписанное разрешение `browser_job` без ручного переноса токена агентом. Нужны вход в тестовое расширение через «Ключ расширения» и авторизованная вкладка нужного маркетплейса.

Если клиент передаёт `PLUGIN_DATA` или `CLAUDE_PLUGIN_DATA`, результаты остаются в каталоге плагина. Иначе MCP использует постоянное хранилище текущего пользователя. Ошибочные явно заданные пути не подменяются.

Поддерживаются текущие WB-инструменты, пакеты promotion/analytics Ozon и защищённая отправка feedback. Ошибка чтения полученного XLSX не требует повторного создания отчёта.

Поколение bridge повышено до 6: прежний primary с другим списком разрешённых расширений корректно завершает активную работу и уступает место новой сборке. Используется обычный локальный адрес bridge; это тестовый вариант для работы с указанным расширением.

## Обновление

Обновите плагин из этого marketplace и начните новую задачу, чтобы клиент загрузил новую конфигурацию. Уведомления об обновлениях и changelog относятся к этому тестовому репозиторию. [Изменения](CHANGELOG.md).
